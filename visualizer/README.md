# RSeries Logic Display Visualizer

A web-based LED matrix visualizer for the RSeries Logic Display system. This tool allows you to preview and test Front Logic Display (FLD) and Rear Logic Display (RLD) animations without requiring the physical hardware.

## Overview

The RSeries Logic Display Visualizer simulates the LED matrices used in R2-D2 and other astromech droids. It provides:

- **Dual Display**: Front (8×10) and Rear (4×28) logic displays with accurate LED mappings
- **Built-in Animations**: Core effects from the Arduino firmware
- **Real-time Preview**: See exactly how animations will look on the hardware
- **MarcDuino Commands**: Generate commands to use with the physical droid
- **No Server Required**: Runs entirely in the browser using ES6 modules

## Features

### Display Support

- **Front Logic Display (FLD)**
  - DeathStar 40 LED (8×10 matrix, 80 LEDs)
  - Curved 40 LED variant
  - Accurate serpentine LED mapping

- **Rear Logic Display (RLD)**  
  - Imahara 112 LED (4×28 matrix, 112 LEDs)
  - Grant Imahara commemorative board
  - Proper physical-to-logical mapping

### Animation Library

**Core Animations:**
- Normal - Default twinkling effect
- Alarm - Fast red/yellow flashing
- Fire - Realistic flame simulation
- Rainbow - Smooth color wheel
- Lights Out - All LEDs off

**Additional Effects:**
- Solid Color, Flash, Color Swap
- Scan Lines, Pulse, Roaming Pixel
- Text scrolling (in development)

### Color System

- 6 built-in color palettes
- HSV color model with smooth transitions
- Brightness, fade, and delay controls
- Hue adjustment for color shifting

## Installation

1. Navigate to the visualizer directory:
   ```bash
   cd RSeriesLogic/visualizer
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Build the project:
   ```bash
   npm run build
   ```

4. Open `dist/index.html` in your web browser

## Usage

### Running Animations

1. Open `dist/index.html` in any modern web browser
2. Select an animation from the categorized buttons
3. Adjust parameters using the sliders:
   - **Brightness**: Overall LED brightness (0-255)
   - **Speed**: Animation speed (0-9)
   - **Fade**: Color transition speed (0-255)
   - **Delay**: Pause between changes (0-255)
   - **Hue**: Global color adjustment (0-255)

4. Choose display options:
   - **Color Palette**: Select from 6 predefined palettes
   - **Target Display**: Both, Front only, or Rear only
   - **Duration**: Time limit for effects (0 = infinite)

### MarcDuino Commands

The visualizer generates MarcDuino commands that can be sent to the physical hardware:

```
:LE00     - Start effect 00 (Normal)
:LEB255   - Set brightness to 255
:LEF128   - Set fade to 128
:LED10    - Set delay to 10
:LEP0     - Use palette 0
```

Click "Copy Commands" to copy them to your clipboard.

### Adding New Animations

1. Create a new file in `src/animations/`:
   ```javascript
   import { createAnimation } from '../core/animation-base.js';
   
   export default createAnimation({
       name: 'my-animation',
       displayName: 'My Animation',
       description: 'Description here',
       category: 'effects',
       effectId: 25,
       interval: 100,
       
       init(params) {
           return { /* initial state */ };
       },
       
       frame(controller, state, params) {
           // Animation logic
           controller.setLED('FLD', index, {r, g, b});
           controller.render();
       }
   });
   ```

2. Add to animation registry in `src/animation-registry.js`
3. Rebuild: `npm run build`

## Technical Details

- **Build System**: esbuild for fast ES6 module bundling
- **Frame Rate**: 100Hz update rate (10ms intervals)
- **Color Model**: HSV with 0-255 ranges
- **Browser Support**: Any modern browser with ES6 module support

## Integration with Hardware

The visualizer uses the same effect IDs and parameter ranges as the Arduino implementation. Commands generated by the visualizer can be sent directly to the RSeries Logic hardware via:

- Serial connection (MarcDuino)
- Web interface (if enabled on ESP32)
- Bluetooth/WiFi (depending on configuration)

## Testing with Puppeteer

The project includes Puppeteer for automated browser testing. This is useful for debugging issues without manually opening a browser.

### Creating a Test Script

```javascript
// test-visualizer.js
const puppeteer = require('puppeteer');
const path = require('path');

async function test() {
    const browser = await puppeteer.launch({
        headless: 'new',
        args: ['--allow-file-access-from-files']
    });
    
    const page = await browser.newPage();
    
    // Monitor console output
    page.on('console', msg => console.log('Browser:', msg.text()));
    page.on('pageerror', error => console.error('Error:', error.message));
    
    // Load the visualizer
    const filePath = `file://${path.join(__dirname, 'dist/index.html')}`;
    await page.goto(filePath);
    
    // Wait for animations to load
    await page.waitForSelector('.animation-button');
    
    // Get animation count
    const buttonCount = await page.$$eval('.animation-button', buttons => buttons.length);
    console.log(`Found ${buttonCount} animations`);
    
    // Take a screenshot
    await page.screenshot({ path: 'visualizer.png' });
    
    await browser.close();
}

test().catch(console.error);
```

### Running Tests

```bash
node test-visualizer.js
```

This allows automated testing of the visualizer without needing to manually check the browser.

## Troubleshooting

**Animation not showing:**
- Ensure brightness is not set to 0
- Check that target display includes the display you're watching
- Verify the animation is properly imported in the registry

**Build errors:**
- Delete `node_modules` and reinstall: `npm install`
- Ensure Node.js version 14+ is installed
- Check file paths don't contain special characters

**Performance issues:**
- Close other browser tabs
- Try a different browser (Chrome/Firefox recommended)
- Reduce animation speed if needed
